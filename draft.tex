\section{XOR Experiments}
Adding scale to a Sinkhorn permutation-finding method is a promising idea, because it enlarges the set of symmetries that can potentially be exploited during alignment. However, even when permutation+scale achieves a lower barrier than permutation alone, that observation is not yet conclusive. It does not by itself show whether scale invariance genuinely unlocks additional symmetry directions and lowers the best attainable barrier, or whether it merely adds more freedom to the optimization and thereby makes the search easier. One possible diagnostic would be to optimize a permutation+scale solution, reset the scales to $1$, and then compare the resulting permutation-only model to a direct permutation baseline. Another alternative is to move to a sufficiently small problem such that exhaustive search over all permutations is feasible. In that setting, the best possible permutation can be identified exactly, and any additional gain from scale can be attributed to scale itself rather than uncertainty about the quality of the permutation search. This is the role of the XOR experiments described below.

\subsection{Methodology}
XOR is studied with small ReLU MLPs of architecture $2$-$h$-$1$, where $h \in \{3,5,7\}$. The number of trained networks was not kept fixed across widths: in the wider settings fewer networks, and therefore fewer model pairs, were used in order to keep the total experiment time manageable. All models were trained on the full XOR dataset, and only solutions that achieve $100\%$ training accuracy and sufficiently low endpoint loss are retained. Thus, every endpoint considered in the pairwise analysis is already a good XOR classifier. This yields $21$ valid model pairs for $h=3$, $36$ valid pairs for $h=5$, and $10$ valid pairs for $h=7$.

For each pair, linear interpolation in parameter space is evaluated under five alignment modes:
\begin{enumerate}[leftmargin=1.5em]
    \item \textbf{No Alignment}: direct interpolation between the two trained endpoints.
    \item \textbf{Sinkhorn Permutation Only (From Scratch)}: a relaxed permutation is optimized from scratch with Sinkhorn and then projected to a hard permutation.
    \item \textbf{Best Exhaustive Permutation}: all hidden-unit permutations are enumerated and the one with the lowest barrier is selected. This is the oracle best result achievable by permutation alone.
    \item \textbf{Sinkhorn Permutation + Scale (From Scratch)}: permutation and positive hidden-unit scalings are optimized jointly from scratch.
    \item \textbf{Best Exhaustive Permutation + Scale Refinement}: first find the oracle best permutation by exhaustive search, then optimize only the scale variables while keeping that permutation fixed.
\end{enumerate}

The purpose of these modes is to separate two different effects. One question is whether a practical relaxed method such as Sinkhorn can \emph{find} the right correspondence between hidden units. A second, and more important, question is whether positive scaling gives a genuine improvement \emph{even after} the best possible permutation has already been found. If the exhaustive permutation can still be improved by a scale-only refinement, then scale is not merely helping the optimizer; it is enlarging the symmetry class that can improve linear mode connectivity.

For the optimization-based methods, a default hyperparameter setting is run first. If that default run fails to satisfy the target criterion, a bounded hyperparameter search is triggered. For the scale-based methods, the target is a small barrier threshold ($\epsilon=0.01$). For Sinkhorn permutation-only, the target is the barrier achieved by the best exhaustive permutation on that same pair. This fallback search is necessary because the effective optimization hyperparameters depend not only on the problem class and architecture, but also on the particular pair of trained networks being aligned.

The main evaluation criterion is the interpolation loss barrier, which measures the largest loss increase encountered along the linear path between two endpoints.

Table~\ref{tab:xor_loss_barrier} is the main quantitative result. As width increases, the best permutation-based alignment becomes substantially more effective: the mean barrier of \emph{Best Exhaustive Permutation} drops from $0.357$ at $h=3$ to $0.111$ at $h=5$ and further to $0.023$ at $h=7$. This agrees with previous findings: wider networks provide more redundancy that can be leveraged by symmetry-based alignment.\\
\newline
The key comparison is then between \emph{Best Exhaustive Permutation} and \emph{Best Exhaustive Permutation + Scale Refinement}: once the best permutation is already fixed, adding scale still reduces the mean barrier from $0.357$ to $0.247$ for $h=3$, from $0.111$ to $0.025$ for $h=5$, and from $0.023$ to $0.005$ for $h=7$. This is the strongest evidence that scaling is not just helping the search procedure; it genuinely improves the best barrier achievable by permutation alone. \\
\newline
The from-scratch \emph{Sinkhorn Permutaion + Scale} method also benefits from scale, especially at $h=5$ and $h=7$ where it beats \emph{Best Exhaustive Permutation} and fails to do that only when $h=3$. It's also consistently better than \emph{Sinkhorn Permutation Only (From Scratch)}.

Table~\ref{tab:xor_pairwise} reports how often the main pairwise method comparisons hold across all valid model pairs. The table compares loss barriers so the lower the better. The strongest result is that \emph{Best Exhaustive Permutation + Scale Refinement} is never worse than \emph{Best Exhaustive Permutation}. So scale reliably improves, or at least preserves, the oracle permutation solution.\\
\newline
By contrast, the from-scratch Sinkhorn permutation solver exactly matches the exhaustive permutation on only $9/21$ pairs for $h=3$, $7/36$ for $h=5$, and $0/10$ for $h=7$, which shows that the Perm-Only method gets stuck in this minimal xor setting even in the presence of hyperparam search.\\
\newline
The joint Sinkhorn permutation+scale method is often better than exhaustive permutation, but not universally. However, it's outperforms the oracle with increasing hidden size.\\
\newline
Overall, the evidence supports the conclusion that permutation symmetry explains a large part of linear mode connectivity, but not all of it. Positive hidden-unit scaling provides a systematic improvement beyond the best permutation alone. Despite that, the joint Sinkhorn Permutation + Scale (From Scratch) method is proven to sometime fail to find those optimal permutations and scales.

\section{Sinkhorn Perm + Scale Experiments on VGGs}
The VGG experiments serve as the large-scale counterpart to the XOR study. On XOR, exhaustive search makes it possible to separate the effect of permutation from the effect of scale exactly. On CIFAR10 with VGG architectures, exhaustive search is no longer feasible, so the question becomes whether the same qualitative pattern persists in a realistic high-dimensional setting. In particular, the goal is to test whether adding scale to Sinkhorn-based alignment lowers the interpolation barrier relative to permutation-only alignment, and whether an additional improvement is obtained by fixing an already found permutation and optimizing only scale on top of it. VGGs on CIFAR10 were chosen intentionally, since this architecture-dataset combination is among the most studied settings in work on the “one basin modulo permutation” hypothesis.

\subsection{Methodology}
The experiment compares three alignment settings on CIFAR10 for fixed endpoint pairs of VGG11, VGG13, VGG16, and VGG19:
\begin{itemize}[leftmargin=1.5em]
    \item \textbf{Sinkhorn Permutation Only}: Sinkhorn permutation parameters are optimized from scratch and then projected to a hard permutation for evaluation.
    \item \textbf{Sinkhorn Permutation + Scale (Joint)}: the same optimization is performed with positive hidden-channel scaling enabled, so permutation variables and scale variables are trained together. During training, the scale variables are optimized jointly with the soft Sinkhorn permutation, while evaluation is performed after projecting the permutation to a hard matching.
    \item \textbf{Permutation Then Scale Finetuning}: the permutation found by the permutation-only run is fixed as a hard permutation, and only the scale variables are optimized afterward.
\end{itemize}
In all cases, the aligned model is compared to the second endpoint by evaluating test loss along the linear interpolation path in parameter space, and the loss barrier is used as the main comparison metric.

Joint Sinkhorn permutation+scale always yields a lower barrier than Sinkhorn permutation-only, indicating that adding scale improves the quality of the connected path beyond what is obtained from permutation search alone. The results do not show a uniform dominance of one scale-based variant over the other. For VGG13 and VGG16, optimizing scale after first fixing the permutation yields a lower barrier than joint permutation+scale optimization, whereas for VGG11 and VGG19 the jointly optimized variant performs better. What is consistent across all four architectures is that adding scale improves over permutation-only alignment. This is also consistent with the XOR results: both scale-based variants improve over Sinkhorn Permutation Only (From Scratch). However, neither of the two scale-based approaches is uniformly better than the other.

\subsection{Open Questions}

Several methodological questions remain open.
\begin{enumerate}[leftmargin=1.5em]
    \item \textbf{Sensitivity to randomness.} The method can remain sensitive to seed-dependent factors such as the train-loader shuffle order. A more rigorous protocol would therefore evaluate each method across repeated runs and report mean and standard deviation rather than a single best outcome.
    \item \textbf{How to aggregate results.} The paper reports both interpolation plots and average barrier summaries, but it is not clear whether the averaging is taken over random restarts, over different endpoint pairs, or over both. This distinction matters because the interpolation curves show one particular result, whereas Figure~\ref{fig:vgg_barriers} summarizes barriers after averaging. For that reason, the reporting protocol should state explicitly what the averaging is taken over. In the references plot, the interpolation curve barrier is lower than the reported average barrier which suggests that in that plot they included the best found permutation.
    \item \textbf{Hyperparameter selection.} The current hyperparameter search was refined iteratively by inspecting earlier results and narrowing the search range. Would a cleaner procedure be to define a fixed search space in advance, select hyperparameters by validation performance within that search, and then report the resulting test barriers without further manual retuning.

\end{enumerate}
